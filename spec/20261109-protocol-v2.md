# Protocol v2

## Summary

The connection between Supa Lookin and SPLKServer is redesigned around three working modes:

- **Inspect**: today's behavior. The Mac window browses the hierarchy, edits attributes and invokes methods.
- **Live Control**: the Mac shows the phone's screen as low-latency video. The user's clicks, drags, pinches, scrolls and shakes on the Mac are replayed on the phone.
- **Takeover**: an MCP client takes control. The Mac window can only watch while agents operate the phone through MCP.

Protocol v1, inherited from Lookin, can't carry these modes:

- Its payloads are `NSKeyedArchiver` object graphs, so both ends must share Objective-C classes and coder keys.
- Its compatibility is a single integer, and the server drops the connection on any request type it doesn't know.
- It has one connection, which large screenshot transfers block.
- It tags requests with second-resolution timestamps, so it discards an older request whenever a newer one of the same type arrives.

v2 replaces it entirely. This spec settles the architecture, the wire format, the session rules, the control model and the schema of the existing features. It reserves the schema for Live Control and Takeover, which later specs implement.

## Principles

- **Debug-only, private APIs allowed.**
  - SPLKServer is a development aid that only compiles in Debug (see `20261109-splk-server.md`). It may use private iOS APIs.
  - The macOS app ships outside the App Store and may use private macOS frameworks.
  - Every private API is reached through runtime lookup (`NSClassFromString`, `NSSelectorFromString`, `dlsym`) and checked before use. A missing symbol disables the feature that needs it instead of crashing.
  - Each such feature is a separate capability, reported only when its check passes.
  - The README tells integrators SPLKServer must never reach an App Store build.
- **No Cocoa types on the wire.** Messages are Protocol Buffers. Images travel as encoded bytes, geometry and colors as numbers, and enums by value. Either end can be written in any language.
- **Features are negotiated, not versioned.** A single protocol generation number (2) guards the framing and session rules. Everything above that is a capability string. A request neither side has a capability for is never sent, and an unknown request gets an `UNIMPLEMENTED` error instead of a dropped connection.
- **Whoever may change the phone is explicit.** Every request is classed as read or mutate, and mutating requests are checked against one control lease (see Control).
- **New code is Swift.** The existing Objective-C hierarchy and attribute builders stay and are called from Swift, following the target-direction rule in `AGENTS.md`.

## Architecture

```
Mac (Supa Lookin)                                   Phone (host app + SPLKServer)
┌──────────────────────────────┐                    ┌──────────────────────────────┐
│ Window UI   Live Control   MCP│                    │ SPLKServerSession (Swift)    │
│      \          |          /  │                    │  ├ session, leases, events   │
│       SPLKDeviceSession actor │   control ───────► │  ├ v1 model → v2 converters  │
│        ├ arbitration (lease)  │   bulk    ───────► │  └ input injection (device)  │
│        ├ v2 → model adapters  │   video (reserved) │ SPLKServer (Objective-C)     │
│        └ host-side backends   │                    │  └ hierarchy/attr builders   │
│          (video, sim input)   │                    └──────────────────────────────┘
└──────────────────────────────┘
        SPLKProtocol (Swift, macOS + iOS): schema, framing, envelope, transport
```

### Package targets

| Target | Language | Platforms | Depends on | Holds |
|---|---|---|---|---|
| `SPLKProtocol` | Swift | macOS, iOS-family | `swift-protobuf` | generated schema, framing, envelope codec, request ids, channel and transport helpers |
| `SPLKServerSession` | Swift | iOS-family | `SPLKProtocol`, `SPLKServer` | the listener, sessions, request routing, converters from `SPLK*` models, leases, events, device-side input |
| `SPLKServer` | Objective-C | macOS, iOS-family | `SPLKServerBase`, `SPLKServerSwift` | the existing models and builders; its v1 connection code is removed |

- The `SPLKServer` product contains `SPLKServerSession`, so host apps link the whole stack.
- `swift-protobuf` is SPLKServer's only third-party dependency. Heavier stacks (gRPC, SwiftNIO) are ruled out, since they would slow host app builds and conflict with the versions host apps already pin.

### Start-up

- `SPLKServerSession` sits above the Objective-C target, so the Objective-C `+load` can't call it directly.
- Instead, `+load` looks up `NSClassFromString(@"SPLKServerBootstrap")` and sends it `start`. That class is the Swift `@objc(SPLKServerBootstrap)` entry point in `SPLKServerSession`.
- SPM links package object files whole, so the class is always present when the product is linked. Integration stays zero-code.

### The Mac side

- One `SPLKDeviceSession` actor per connected app owns its connections, request ids, subscriptions and lease state.
- The window, Live Control and each MCP session are clients of that actor, each with its own identity. None of them touches a connection directly.
- The actor converts v2 messages into the existing `SPLK*` Objective-C models, so the window's views keep working unchanged at first.
- Host-side backends for video and simulator input live beside the actor (see Live Control).

## Transport

- **Ports**: unchanged from `20261109-splk-server.md`, 47264–47269 for the simulator and 47275–47279 for USB devices. The server listens with `NWListener` on `127.0.0.1`.
- **Reaching the device**:
  - On a USB device, the Mac opens connections through usbmuxd, reusing `SPLK_PTUSBHub` to get a connected socket. Nothing of Peertalk's framing remains.
  - On the simulator, the Mac connects to localhost.
- **One session, several connections**: every connection opens with a `ChannelHello` naming its role.

  | Role | Carries | Rule |
  |---|---|---|
  | `CONTROL` | every RPC except bulk transfers, events, input | Small messages, `TCP_NODELAY`. Opened first; its `ServerHello` creates the session. |
  | `BULK` | screenshots, hierarchy details, images | Opened right after `CONTROL` with the session id. Large items are split into stream chunks of at most 1 MiB, so one transfer never holds the link for long. |
  | `VIDEO` | encoded frames from the phone | Reserved for in-app capture (`video.inapp.h264`). Never queues: a frame that can't be sent before the next one is dropped. |

- **One session per app**: a new `CONTROL` connection replaces the current session and closes its connections. This matches v1's behavior, where the newest client wins.
- **Liveness**: the client sends a `Heartbeat` on `CONTROL` every 2 s. The server ends a session it hasn't heard from in 6 s. Ending a session releases its lease.

## Framing

Every frame is a 12-byte header followed by the payload. All integers are big-endian.

| Offset | Size | Field |
|---|---|---|
| 0 | 4 | magic `SPLK` (`0x53504C4B`) |
| 4 | 1 | frame format, `1` |
| 5 | 1 | kind: `0` = `Envelope`, `1` = video packet |
| 6 | 2 | flags, `0` (reserved) |
| 8 | 4 | payload length, at most 16 MiB |

- A bad magic, an unknown format or an oversized length closes the connection.
- **v1 never misreads a v2 frame, and v2 never misreads a v1 frame:**
  - A v1 server reads the magic as a Peertalk version and rejects it.
  - A v2 server sees a v1 frame's first word, `1`, and rejects it.
  - When the connection closes before a `ServerHello`, the Mac reports the app's SPLKServer as incompatible and asks for an upgrade.

## Session

### Handshake

1. The client sends `ClientHello` with the protocol generation, its name and version, the capabilities it understands, and the channel role.
2. The server answers `ServerHello` with:
   - its generation and readable version;
   - a session id;
   - its capabilities;
   - an `AppSummary`: what v1's `App` request returned, without images, plus a `ScreenInfo` (screen size in points, scale, orientation, safe area insets).

   A generation mismatch sets an error status in `ServerHello` and closes the connection.

- **Discovery**: the Mac's app list is the set of completed handshakes on the scanned ports. `GetAppInfo` is only needed for the screenshot and icon.
- **Enabled features**: a feature is enabled only when both sides list its capability.

### Envelope and requests

Every payload on `CONTROL` and `BULK` is an `Envelope`: one request, response, stream item, stream end, cancel, event or heartbeat, tagged with a 64-bit id.

- **Request ids**: the client numbers its requests from 1, increasing per session, and every message about a request carries its id. Ids are never reused within a session.
- **Shapes**:
  - **unary**: one `Response`;
  - **server-streaming**: any number of `StreamItem`s, then a `StreamEnd` with the final status;
  - **one-way**: `Request.oneway`, with no reply unless it fails.
- **Deadlines**: each request carries `deadline_ms`, and 0 means the method's default. The server abandons work past the deadline and answers `DEADLINE_EXCEEDED`. Streams restart their deadline on every item, as v1's multi-response timeout did.
- **Cancellation**: `Cancel{id}` stops a request. A cancelled stream ends with `CANCELLED`. This replaces v1's `SPLKPush_CanceHierarchyDetails`.
- **No discarding**: v2 never drops a request because a newer one of the same kind arrived.
  - v1 did this in the transport. In v2 the window decides for itself, by cancelling its own superseded requests.
  - An MCP session's requests are never cancelled by the window's.
- **Errors**: every failure is a `Status`, containing:
  - a code: `OK`, `CANCELLED`, `INVALID_ARGUMENT`, `NOT_FOUND`, `DEADLINE_EXCEEDED`, `UNIMPLEMENTED`, `FAILED_PRECONDITION`, `PERMISSION_DENIED`, `RESOURCE_EXHAUSTED`, `INTERNAL`;
  - a `reason` string for the specific case (`app_in_background`, `object_deallocated`, `lease_required`, `lease_revoked`, …);
  - an optional localized title and detail for display.
- **Background state**: v1's ping-before-every-request is gone. A request that needs the app in the foreground fails with `FAILED_PRECONDITION` / `app_in_background`. The `app_state` event reports transitions.

### Events

- `Subscribe{topics}` is a server-streaming request whose items are `Event`s. Cancelling it unsubscribes.
- Topics:
  - `app_state`: foreground or background;
  - `screen`: orientation or size change;
  - `control`: lease acquired, released or revoked;
  - `hierarchy_changed`: the layer tree committed changes. Coalesced to at most 10 per second and gated by `events.hierarchy`;
  - `idle`: the main run loop is idle with no running animations. Gated by `wait.idle`.

## Control

### Modes

| Mode | Lease | Window may read | Window may mutate | Input source |
|---|---|---|---|---|
| Inspect | none | yes | yes | none |
| Live Control | held by the window, kind `LIVE_CONTROL` | yes | yes | the user, through the Live Control view |
| Takeover | held by one MCP session, kind `TAKEOVER` | yes | no | that MCP session |

Transitions:

```
Inspect ──(user starts Live Control)──► Live Control ──(user stops)──► Inspect
   │  ▲                                     │
   │  └──────────(release / revoke / expiry)─┼───────────┐
   └──(MCP acquires)──► Takeover ◄──(MCP acquires; preempts Live Control)
```

### Leases

- Arbitration lives in `SPLKDeviceSession` on the Mac, the only place that knows whether a request comes from the window, Live Control or which MCP session.
- **Acquiring**: the Mac acquires a lease on the phone with `AcquireControl{kind, holder_label, preempt}` and gets back a `lease_id`.
- **Enforcement on the phone**:
  - While a lease is held, every mutating request must carry its `lease_id`. Any other mutating request gets `PERMISSION_DENIED` / `lease_required`.
  - With no lease held (Inspect), mutating requests need none.
  - Read requests never need a lease.
- **The phone also shows the holder**: `holder_label` (for example "Claude Code") feeds an on-device indicator while a `TAKEOVER` lease is held. The indicator lives in a window SPLKServer excludes from every hierarchy it reports.
- **MCP leases expire**: an MCP holder renews through the MCP layer at least every 30 s. When it stops, `SPLKDeviceSession` releases the lease. A crashed agent can't lock the phone.
- **The person at the Mac always wins**:
  - The window always offers "Take Back Control".
  - It revokes any `TAKEOVER` lease (`ReleaseControl` followed by the window's own `AcquireControl` with `preempt`).
  - The agent's later requests fail with `PERMISSION_DENIED` / `lease_revoked`.
- **One holder at a time**:
  - A second MCP session that asks to take over is refused while another holds the lease.
  - It can still read.
- **Leases end with the session**: a closed session releases its lease on the phone.

### Takeover visibility

During Takeover the window shows, read-only:
- the live video;
- the hierarchy, refreshed on `hierarchy_changed`;
- an action log. `SPLKDeviceSession` records each mutating request an MCP session sends and marks touch points on the video.

## Live Control

### Video

Video is captured on the Mac whenever possible, with nothing running in the app:

| Target | Backend | Notes |
|---|---|---|
| USB device | CoreMediaIO with `kCMIOHardwarePropertyAllowScreenCaptureDevices`, read through AVFoundation | The mechanism QuickTime's device mirroring uses. Full screen at up to 60 fps. |
| Simulator | SimulatorKit/CoreSimulator framebuffer (private) | No screen-recording permission, no window capture. |

- **In-app capture** (`video.inapp.h264`) is reserved for connections where neither applies, such as Wi-Fi:
  - ReplayKit capture, encoded by VideoToolbox (H.264, real-time, low-latency rate control, no B-frames);
  - sent as NAL units on `VIDEO`;
  - shown with `AVSampleBufferDisplayLayer`.
- **Mapping clicks onto the phone**:
  - Every input event uses coordinates normalized to the screen (0–1, origin at the top left of the current orientation).
  - The Mac maps the video rect to them using `ScreenInfo`, so the video's pixel size never matters.
- **Latency target**: under 100 ms from a Mac click to the phone frame showing its effect.

### Input

Input is sent as `InjectInput{events}`, a one-way request on `CONTROL`, holding one or more `InputEvent`s:

- **Touches**: `touch_id`, phase (`began`, `moved`, `stationary`, `ended`, `cancelled`), normalized point, optional force, client timestamp.
  - Pinch and rotate are two touch ids. The Mac turns trackpad magnify/rotate gestures, and option-drag, into two-finger paths.
  - Scroll-wheel input becomes a one-finger drag.
- **Motion**: `shake`.
- **Text**: a string to insert, plus key presses (return, delete, arrows).

Delivery rules:
- The Mac coalesces `moved` events to the display rate.
- `began`, `ended` and `cancelled` are never dropped or merged.
- The phone injects on the main thread at the next display-link tick.

There are two injection backends. The Mac chooses one when Live Control or Takeover starts:

| Backend | Where | How | Reaches | Capability |
|---|---|---|---|---|
| Host-side | Mac, simulator only | SimulatorKit HID injection (private), the path Simulator.app uses | the whole simulator, system UI included | — (Mac-local) |
| Device-side | SPLKServer | `IOHIDEvent` synthesis enqueued into UIKit (private), like KIF and EarlGrey. Shake goes through `motionBegan`/`motionEnded`. | the host app's own windows, while it is in the foreground | `input.touch`, `input.motion`, `input.text` |

The simulator prefers the host-side backend. A USB device uses the device-side backend. System UI on a device (permission alerts, the home screen) is outside reach. Whether the device-side backend reliably delivers one-finger drags, two-finger pinches and shakes on iOS 27, on simulator and device, is settled by a spike before its milestone spec.

## Takeover for agents

Agents need to act, wait for the result and look again. Besides raw input, v2 reserves:

- **`PerformAction{node, action}`**: semantic actions on a hierarchy node.
  - Actions: `tap`, `long_press`, `set_text`, `scroll_to_visible`, `scroll_by`, `swipe`, `go_back`.
  - `tap` prefers `accessibilityActivate` or `sendActions(for:)`, and falls back to a synthesized touch at the node's center.
  - It answers after the UI settles, with the new hierarchy version.
  - Capability `action.semantic`.
- **`WaitForIdle{timeout_ms}`**: returns once the `idle` condition holds, or on timeout. Capability `wait.idle`.
- **Hierarchy versions**:
  - Every `HierarchySnapshot` carries a version that increases per session.
  - `GetHierarchy{since_version}` may answer with a diff when `hierarchy.diff` is negotiated.
  - Until then it always answers with the full tree.
- **Screenshots for agents**: MCP's screenshot tool reads the latest Live Control video frame when video is running, instead of asking the phone to render one.

The MCP tools that drive these are specified separately. The read-only tools of `20261025-mcp-server.md` keep working on top of `SPLKDeviceSession`.

## Methods

Every existing v1 request has a v2 method with the same meaning:

| v2 method | v1 request | Shape | Class | Channel | Capability |
|---|---|---|---|---|---|
| `GetAppInfo` | `App` (201) | unary | read | control | `app` |
| `GetHierarchy` | `Hierarchy` (202) | unary | read | bulk | `hierarchy` |
| `FetchDetails` | `HierarchyDetails` (203) | stream | read | bulk | `details` |
| `ModifyAttribute` | `InbuiltAttrModification` (204) | unary | mutate | control | `attr.modify` |
| `FetchModificationPatch` | `AttrModificationPatch` (205) | stream | read | bulk | `attr.modify` |
| `InvokeMethod` | `InvokeMethod` (206) | unary | mutate | control | `object.invoke` |
| `GetObject` | `FetchObject` (207) | unary | read | control | `object` |
| `GetImageViewImage` | `FetchImageViewImage` (208) | unary | read | bulk | `image` |
| `SetGestureRecognizerEnabled` | `ModifyRecognizerEnable` (209) | unary | mutate | control | `gesture.toggle` |
| `GetAttributeGroups` | `AllAttrGroups` (210) | unary | read | control | `attr.groups` |
| `ListSelectors` | `AllSelectorNames` (213) | unary | read | control | `object.selectors` |
| `ModifyCustomAttribute` | `CustomAttrModification` (214) | unary | mutate | control | `attr.custom` |
| `Cancel` | push `CanceHierarchyDetails` (304) | — | — | either | (core) |

`Ping` (200) is replaced by the handshake and heartbeats. Push 303, already unused, has no successor.

Reserved for later milestones:

| v2 method | Shape | Class | Capability |
|---|---|---|---|
| `AcquireControl`, `ReleaseControl` | unary | — | `control.lease` |
| `Subscribe` | stream | read | `events` (plus per-topic capabilities) |
| `InjectInput` | one-way | mutate | `input.touch`, `input.motion`, `input.text` |
| `PerformAction` | unary | mutate | `action.semantic` |
| `WaitForIdle` | unary | read | `wait.idle` |

## Schema

`Sources/SPLKProtocol/Schema/splk.proto` (package `splk.v2`) holds the schema. Generated Swift is committed, so building SPLKServer needs no `protoc`.

The rules for changing it:
- Field numbers are never reused or renumbered. Removed fields become `reserved`.
- New fields are optional by nature.
- New methods take new `oneof` cases.

### Session messages

```proto
syntax = "proto3";
package splk.v2;

enum ChannelRole {
  CHANNEL_ROLE_UNSPECIFIED = 0;
  CHANNEL_ROLE_CONTROL = 1;
  CHANNEL_ROLE_BULK = 2;
  CHANNEL_ROLE_VIDEO = 3;
}

message ClientHello {
  uint32 protocol_generation = 1;   // 2
  string client_name = 2;
  string client_version = 3;
  repeated string capabilities = 4;
  ChannelRole role = 5;
  bytes session_id = 6;             // empty on CONTROL; the ServerHello's id on the others
}

message ServerHello {
  Status status = 1;
  uint32 protocol_generation = 2;
  string server_version = 3;        // SPLK_SERVER_READABLE_VERSION
  bytes session_id = 4;
  repeated string capabilities = 5;
  AppSummary app = 6;
}

message Envelope {
  uint64 id = 1;
  oneof body {
    Request request = 2;
    Response response = 3;
    StreamItem stream_item = 4;
    StreamEnd stream_end = 5;
    Cancel cancel = 6;
    Event event = 7;
    Heartbeat heartbeat = 8;
  }
}

message Request {
  uint32 deadline_ms = 1;
  bytes lease_id = 2;
  bool oneway = 3;
  oneof call {
    GetAppInfo get_app_info = 10;
    GetHierarchy get_hierarchy = 11;
    FetchDetails fetch_details = 12;
    ModifyAttribute modify_attribute = 13;
    FetchModificationPatch fetch_modification_patch = 14;
    InvokeMethod invoke_method = 15;
    GetObject get_object = 16;
    GetImageViewImage get_image_view_image = 17;
    SetGestureRecognizerEnabled set_gesture_recognizer_enabled = 18;
    GetAttributeGroups get_attribute_groups = 19;
    ListSelectors list_selectors = 20;
    ModifyCustomAttribute modify_custom_attribute = 21;

    AcquireControl acquire_control = 40;
    ReleaseControl release_control = 41;
    Subscribe subscribe = 42;
    InjectInput inject_input = 43;
    PerformAction perform_action = 44;
    WaitForIdle wait_for_idle = 45;
  }
}

message Response {
  Status status = 1;
  oneof result {
    AppInfo app_info = 10;
    HierarchySnapshot hierarchy = 11;
    NodeDetail node_detail = 13;
    InvokeResult invoke_result = 15;
    ObjectRef object = 16;
    EncodedImage image = 17;
    bool gesture_enabled = 18;
    AttributeGroupList attribute_groups = 19;
    StringList selectors = 20;
    Empty empty = 21;

    ControlLease lease = 40;
    ActionResult action_result = 44;
  }
}

message StreamItem {
  oneof item {
    NodeDetail node_detail = 1;     // FetchDetails, FetchModificationPatch
    Event event = 2;                // Subscribe
  }
}

message StreamEnd { Status status = 1; }
message Cancel {}
message Heartbeat {}
message Empty {}
message StringList { repeated string values = 1; }

message Status {
  enum Code {
    OK = 0;
    CANCELLED = 1;
    INVALID_ARGUMENT = 2;
    NOT_FOUND = 3;
    DEADLINE_EXCEEDED = 4;
    UNIMPLEMENTED = 5;
    FAILED_PRECONDITION = 6;
    PERMISSION_DENIED = 7;
    RESOURCE_EXHAUSTED = 8;
    INTERNAL = 9;
  }
  Code code = 1;
  string reason = 2;
  string title = 3;
  string detail = 4;
}
```

## Converters

- **Phone**: `SPLKServerSession` calls the existing Objective-C builders (`SPLKHierarchyInfo staticInfoWithSPLKVersion:`, `SPLKHierarchyDetailsHandler`, `SPLKInbuiltAttrModificationHandler`, …) and converts their `SPLK*` results to v2 messages.
  - Images are encoded as PNG when they have transparency and JPEG otherwise, at the quality v1's `SPLKDisplayItem` encoding used.
  - Attribute values map by `AttrType`, as in the `Value` comments. The M2 spec lists the value shape of every attribute identifier, custom attributes included. A value that fits no `Value` case gets a new case, not an ad hoc encoding.
  - Where v1 sent the client's readable version (`clientVersion`, `clientReadableVersion`), the converter passes `ClientHello.client_version`.
  - `InvokeResult.returns_void` replaces v1's `SPLKStringFlag_VoidReturn` description.
  - The Objective-C v1 entry points (`SPLKConnectionManager`, `SPLKRequestHandler`) are deleted.
- **Mac**: `SPLKDeviceSession` converts v2 messages back to the same `SPLK*` classes and hands them to today's views.
  - `SPLKAppInfo` fields with no v2 counterpart are filled on the Mac: `serverReadableVersion` from `ServerHello.server_version`, and `swiftEnabledInSPLKServer` as `1`.
  - The window, the dashboard and the MCP tools are untouched by M3, apart from their calls into the connection, which move to the actor.
  - `.supalookin` and `.lookin` documents keep their current `NSKeyedArchiver` format, written and read on the Mac from those classes.

## Compatibility

- **No coexistence with v1**: a v2 Mac and a v1 server reject each other's first frame (see Framing).
  - The Mac shows the existing "version too low" message for an app that closes the connection before a `ServerHello`.
  - It also shows it for one whose `ServerHello` reports another generation.
- The constants `SPLK_SERVER_VERSION`, `SPLK_CLIENT_VERSION`, `SPLK_SUPPORTED_SERVER_MIN` and `SPLK_SUPPORTED_SERVER_MAX` are removed. Their compatibility role belongs to the protocol generation and capabilities.
- `SPLKHierarchyFile.serverVersion` stays in documents and is set to `1` for new ones, so existing `.supalookin` files keep opening.
- `SPLK_SERVER_READABLE_VERSION` stays. It travels in `ServerHello.server_version` and still drives the outdated-server hint.

## Milestones

Each milestone gets its own spec before implementation.

| Milestone | Scope |
|---|---|
| M1 Protocol core | `SPLKProtocol`: schema, generated code, framing, envelope codec, handshake, request ids, deadlines, cancellation, heartbeats. Unit tests over in-memory transports. |
| M2 Server | `SPLKServerSession`: listener, sessions and channels, every existing method with converters, the bootstrap. v1 server code removed. |
| M3 Mac | `SPLKDeviceSession`, the usbmux and localhost transports, adapters, the window and MCP moved onto the actor. v1 client code removed. Ships together with M2. |
| M4 Control and events | Leases, the mode state machine, `Subscribe` with `app_state`, `screen`, `control`; Takeover's read-only window and action log. |
| Spike | Device-side input on iOS 27 (simulator and device): one-finger drag, pinch, shake, text. Decides M5's device backend. |
| M5 Live Control | Mac-side video (CoreMediaIO, SimulatorKit), host-side and device-side input, the Live Control view. |
| M6 Agents | `PerformAction`, `WaitForIdle`, `hierarchy_changed`, `idle`, the MCP write tools and Takeover. |
| Later | `hierarchy.diff`, in-app video, Wi-Fi discovery. |

## Verification

For M1–M3, which replace v1:
- `SPLKProtocol` tests:
  - framing round trips;
  - handshake, including a generation mismatch;
  - unary, streaming, one-way, cancel, deadline;
  - unknown methods return `UNIMPLEMENTED`;
  - no request is discarded by another of the same kind.
- **Converter round trips**: every `SPLK*` model of a recorded hierarchy goes Objective-C → v2 → Objective-C and compares equal.
- **End to end**: against an app on the simulator and on a USB device, every row of the Methods table behaves as it did in v1, and the MCP read-only tools work while the window syncs.
- **v1 rejection**: a v1 app (SPLKServer 1.0.15) shows the version message instead of hanging.
- **Large transfers don't block control**: a details fetch of over 20 MB doesn't delay a concurrent `GetObject` by more than 50 ms.

## Out of scope

- Moving documents to a protobuf format.
- Wi-Fi connections and Bonjour discovery.
- Clients or servers on other platforms; the schema only makes them possible.
- Authentication on the device link. Like v1, any local process that can reach usbmuxd or localhost can connect. The MCP bearer token guards only the Mac's MCP port.
